# Полный ребрендинг Ansible для macOS

План выполнения и передачи работы, 15 ноября 2026. Цель — цельный нативный клиент Ansible с понятными названиями, согласованными изображениями и переводами. Существующие размеры, сетки и поведение macOS служат основой; фирменные элементы получают собственные мастера и явные роли.

## 1. Исходное состояние

Рабочая база: `ansible-ios/app-macos`, master `28f988e7` поверх первоначального импорта `3732e65e`. Это Swift/AppKit-клиент, отдельный от Qt Desktop и мобильного iOS. Проверено по исходникам и публичным langpack RPC через существующие сессии Ansible/Telegram.

Сохранить чужие изменения: dirty `submodules/ansible-ios` содержит применённые патчи; `.vscode/` не относится к ребрендингу. Сабмодуль не коммитить случайным gitlink. Перед реализацией повторить status/HEAD: этот документ не даёт права затереть последующую работу.

| Область | Что уже есть | Что ещё требуется |
| --- | --- | --- |
| Идентичность | Ansible, `com.ansible.macos`, отдельные каталог и keychain scope | Проверка всех системных поверхностей и extension-конфигураций |
| Сеть | Собственные DC/RSA, Ansible credentials, отключён Telegram bootstrap | Регрессия авторизации и ссылок после ребрендинга |
| Ссылки | `as://`, `asme.su`, `ansible.su` | Проверка каждого генератора, QR, копирования и fallback |
| Иконка приложения | Одобренная тёмная иконка Ansible | Сохранить внешний вид, проверить все размеры/варианты Icon Composer |
| Алмазы | Часть статических PNG, inline-анимаций и scene уже заменена | Единый язык формы во всех состояниях, размерах и типах рендера |
| Строки | Встроенный English уже использует Ansible; backend отдаёт «Мои алмазы» | Покрытие новых ключей, формы чисел, hardcoded UI, системные строки |
| Происхождение | README/NOTICE/LICENSE сохраняют upstream attribution | Сохранить при всех переименованиях; GPL v2 в этом репозитории |

Предыдущая папка `_tmp/media/app-macos-gpt` — рабочие материалы. Её README и mapping описывают первоначальный набор, а не полный список установленного: commit `28f988e7` применил 32 PNG. Нельзя слепо заливать всю папку поверх клиента. Нужен новый манифест «источник → роль → потребитель → экспорт → проверка».

## 2. Зафиксированные решения владельца

- Название продукта: **Ansible**; публичные продуктовые тексты не называют его Telegram.
- Приложение сохраняет одобренную **тёмную иконку с логотипом Ansible**.
- Образец цветного алмаза: предоставленный `diamond-DeqvJf1W.webp`; не заменять случайным emoji 💎 или другой геометрией.
- Нужны согласованные варианты этого алмаза: цветной; монохромный для меню; вариант в скруглённом квадрате для настроек.
- Внутренняя валюта называется **Алмазы / Diamonds**.
- Оформление сохраняет качество и плотность нативного macOS-интерфейса: согласованные пропорции, прозрачность, отступы, типографика, взаимодействие с темой.
- Схема приложения — **`as://`**. Публичные ссылки — **`asme.su`**, информационные страницы — проверенные маршруты **`ansible.su`**.
- README сохраняет указание на fork Telegram и авторство upstream. Имя продукта и лицензирование решаются раздельно.

Текущие пользовательские обои, выбранная тема и содержимое сообщений не являются объектом ребрендинга.

## 3. Дизайн системы бренда

### Логотип приложения

Хранить один исходный мастер знака Ansible и экспортировать нужные размеры из него. Сохранить контур, толщину линии и текущую тёмную подложку. Проверить Dock, Cmd-Tab, Finder, About, уведомления, авторизацию, share extension и иконку файла/протокола, если она используется. Не оставлять маленький логотип внутри уже скруглённой рамки, поверх которой система добавит вторую рамку.

### Роли алмаза

| Роль | Исполнение | Приёмка |
| --- | --- | --- |
| Настройки | Алмаз в скруглённой цветной плитке | Оптический размер совпадает с соседними иконками; нет белого прямоугольника |
| Баланс и цены | Цветной алмаз на прозрачном фоне | Базовая линия и интервал согласованы с числом; различим на светлой/тёмной теме |
| Меню и toolbar | Template-иконка с alpha-маской | Системный tint, hover, selected и disabled; RGB картинки не мешает перекраске |
| Мелкий inline | Упрощённые грани того же силуэта | Читается в 12–16 pt, не превращается в синее пятно |
| Крупный hero | Вектор или 3D-модель той же формы | Материалы и грани согласованы с маленьким знаком; без звезды в idle/переходе |
| Анимация | Lottie/scene/Metal с тем же силуэтом | Проверены первый, промежуточные, последний кадры и Reduce Motion |
| Premium | Отдельная роль в палитре Premium | Отличается от денежного баланса, использует согласованный фирменный знак |

Размеры брать из фактических потребителей. Для Retina проверить 1x/2x и дробный scale. Единые токены должны задавать оптическую рамку, отступы, контраст, stroke, радиусы и материалы. Значения существующего `design-tokens.json` — черновик; их нужно согласовать с реальным образцом и текущими native palette/tint API.

Отдельно классифицировать звезду как валюту, Premium-символ, оценку звонка, геометрическую фигуру или пользовательский контент. Валютные поверхности обязательно становятся алмазами. Оценка звонка и фигура в редакторе сохраняют своё функциональное значение. Текущий English содержит такие корректные `Star/Stars` — grep не является визуальной приёмкой.

### Инвентаризация

В директориях `Telegram-Mac`, `Resources`, `packages` найдено 3098 исходных медиафайлов выбранных форматов: 2612 PNG, 42 PDF, 47 SVG, 383 TGS, 6 JPG и 8 SCN. Имена 191 файла попали в предварительную выборку для ручной классификации; это не утверждение о 191 неверной картинке.

Проверить дополнительно программно нарисованные символы, `theme.icons`, SF Symbols, glyphs, строковые emoji, package resources и картинки, пришедшие с сервера. Имя `Star` в файле после замены само по себе не доказывает наличие звезды на экране.

## 4. Нужны ли macOS собственные переводы

**Да. Уже используется отдельная платформа `macos`; новый сервис не нужен.**

Тракт: `ApiEnvironment.language = "macos"` → `NetworkInitializationArguments.languagesCategory` → `MTApiEnvironment.langPack` → `langpack.*` → backend `rpc_langpack`/`langpack_source` → `as-translations-api` → language cache → `Localization._LocalizedStringFor`.

Share extension также берёт `ApiEnvironment.language`. Ключи macOS отличаются от iOS и Qt Desktop. Из 9448 ключей встроенного English только 1261 совпал с развёрнутым эталонным iOS en. Общие идеи перевода переносить можно; чужой langpack целиком — нельзя.

`lang_pack` — идентификатор платформы по [официальному контракту getLangPack](https://core.telegram.org/method/langpack.getLangPack). Эталон получен с живого Telegram, а не только из документации.

### Измеренное покрытие

Для сопоставления TL pluralized strings развёрнуты в формы `key_zero`, `key_one`, `key_two`, `key_few`, `key_many`, `key_other` — как делает macOS. Поэтому числа форм больше числа TL-объектов.

| Метрика | English | Русский |
| --- | ---: | ---: |
| Встроенные ключи/формы клиента | 9448 | тот же контракт |
| Telegram macos, TL-объекты | 9060 | 9867 |
| Ansible macos, TL-объекты | 8162 | 8329 |
| Telegram macos, развёрнутые ключи/формы | 9410 | 10983 |
| Ansible macos, развёрнутые ключи/формы | 8493 | 9352 |
| Ключи/формы клиента, отсутствующие у Ansible | 1632 | 1464 |
| Из них доступны у Telegram | 898 | 1449 |
| Ключи клиента, отсутствующие и у Telegram | 734 | 15 |

Это покрытие контракта bundled strings, а не процент готовности всех экранов. Встроенные неанглийские Localizable.strings сейчас не дают полезного полного набора; основной fallback — English. Пробелы облачного русского пакета поэтому могут проявляться английскими фрагментами.

На сервере уже есть `AccountSettings.Stars = "Мои алмазы" / "My Diamonds"`. Проверка отсутствующих ключей не обнаружила решений через простое сопоставление `Stars→Diamonds`/`Telegram→Ansible`: новая массовая миграция имён ключей сейчас не обоснована. Сохранить действующий контракт и исправлять значения/покрытие.

### Снятые данные

Сохранены все 25 заявленных macOS-языков Ansible и Telegram: 203455 и 236990 TL-записей соответственно. Первичные снимки неизменны, рядом манифесты и SHA-256. Подготовлено 31744 кандидата на добавление только в отсутствующие у клиента формы. 2261 кандидат отмечен эвристическими флагами проверки бренда, format arguments или пустого значения. Это очередь проверки, не готовый seed.

Артефакты: `_tmp/macos-rebrand-20261115/reference/{as,tg}`, `audit-summary.json`, `localization-gaps.csv`, `translation-review/manifest.json`, `translation-review/worklist.csv`. Никаких session/auth_key/credentials в этих файлах нет.

### Безопасный импорт

1. Зафиксировать текущие platform/language versions и полный экспорт macos со статусами `base/approved`, удалить ли только явно одобренное — решать отдельно. Сохранить резервную копию и diff.
2. Использовать свежий TG `macos` как источник недостающих переводов; сохранить текущие Ansible-значения, ручные approved правки, старые native keys и custom packs.
3. Для каждого нового текста проверить смысл, ссылки, plural forms, форматирование и продуктовые возможности. Сохранить исходный TG текст отдельно от Ansible overlay.
4. В первую очередь довести en/ru; для остальных 23 языков держать измеримое покрытие и явные fallback. Не выдавать английский текст под другим языковым кодом за готовый перевод.
5. Сформировать **полный снимок платформы macos**, либо реализовать явный additive/scoped import через сервис переводов. Нельзя подавать в текущий seed только 1449 строк или только en/ru: `bht_seed:merge_platform` пометит отсутствующие base-строки объявленной платформы удалёнными.
6. Не запускать `scripts/update_seed.py` для одного macOS: он удаляет весь существующий каталог seed, включая остальные платформы. Новый экспорт должен иметь platform allowlist, manifest/checksums и fail-closed dry-run.
7. Проверить, что запуск не является первым разрушительным seed. Approved/custom строки сохраняются; прежние base значения нельзя возвращать сырым TG seed без диффа.
8. Клиентский fallback, seed и серверные overrides должны иметь один словарь бренда. Не вписывать ребрендинг runtime-заменой любого произвольного текста пользователя.
9. После релиза проверить `getLanguages`, `getLanguage`, `getLangPack`, `getStrings`, `getDifference`; применение `updateLangPack`/`updateLangPackTooLong`, переключение языка, reconnect и уже сохранённую версию пака.
10. Проверить возврат при недоступном сервисе переводов: ошибка не превращается в пустой пак или массовые Deleted, работающий локальный язык сохраняется.

Тестовые числа: 0, 1, 2, 5, 11, 21, 101 и большие суммы. Сверять `%@/%d/%f`, позиции `%1$@`, escaped percent, ссылки и Markdown/entity-разметку. Пустой перевод и отсутствие перевода различать. Добавить RTL/длинные строки/VoiceOver и системные InfoPlist/Menu/Share строки, которые не всегда идут через langpack.

**Статус сейчас:** все исходные пакеты скачаны, пробелы и очередь подготовлены. Импорт в живую БД и выпуск переводов не выполнялись: кандидаты ещё не прошли смысловую/брендовую проверку. Существующая платформа macos работает и остаётся источником текущих переводов.

`Gram`, TON и XTR — не просто слова для замены. Нельзя переименовать чужой денежный инструмент в «Алмазы», оставив его операции, цену, сеть и комиссии прежними. При аудите URL найдено 87 строк-кандидатов: 15 production и 72 test. Каждую разобрать по роли: собственная навигация, документирование происхождения, пользовательская ссылка или внутренний entity marker. `tg://user?id` внутри сериализации mention нельзя заменять как обычную публичную ссылку. Список найденного — `upstream-url-candidates.json`.

Батчи коммитов небольшие и независимые: contract/inventory, translation tooling/data, static assets, animation/scene, UI surfaces, system metadata и release evidence. Коммитить только своё от WhYasha, проверяя author/committer и GitHub association. UI-модели не раздувать ради общих hardcoded строк: пользоваться существующими package boundaries и hooks. Не собирать backend локально ради релиза и не запускать TeamCity как read-only compile check.

Данные переводов публиковать через штатный процесс `as-translations-api`, backend менять лишь при доказанной потребности. TeamCity build-type и import operation сначала прочитать: смена образа сама по себе не доказывает обновление уже наполненной БД. У backend build выпуск автоматический; для обычного master queue — только buildType без custom revisions. Наблюдать всю цепочку до rollout/health.

## 7. Проверка готовности

- Для каждого экрана из раздела5 есть владелец батча, before/after и статус PASS/FAIL/BLOCKED; «не проверено» не превращается в PASS.
- На активных собственных поверхностях нет Telegram product branding, валютных звёзд, сторонних CTA и неподдерживаемых финансовых обещаний. Нейтральные рисунки, чужие сообщения и лицензии классифицированы отдельно.
- Новая установка без сети показывает Ansible и понятный English fallback; русский язык после загрузки покрывает приоритетные сценарии. При обновлении локализация не откатывается и не теряет формы.
- Сравнить login, settings, balance, transaction/refund, paid reaction/message, gift, Premium, links/QR, notification/share, About и ошибки на light/dark/auto, Retina и малом окне. Системная тема пользователя не сбрасывается.
- Проверить межклиентские операции с iOS/Desktop по одним тестовым данным. Согласованная терминология не означает одинаковые размеры или копирование UIKit-layout в AppKit.
- Сессионный e2e: старый macOS и новый, обновлённый/старый langpack cache, getDifference, параллельное обновление языка. Остальные платформы и approved/custom packs не меняются от macos-only импорта.
- Клиентские smoke: запуск arm64, подпись, URL handlers, Share availability, отсутствие новых сетевых запросов к Telegram bootstrap/update endpoints. Рабочие user sessions, drafts, custom themes и secret chats сохранены.
- Производительность: обычные списки без постоянных hero-анимаций; CPU/память/скролл проверить на том же Mac. Локальная сборка ограничена по jobs; приложение перезапускать с учётом текущей работы владельца.
- Security review: ссылки и QR не раскрывают токены, собственные URL не принимают похожие чужие hostnames, capabilities не обходят backend-права, в коммитах нет ключей/сессий/переписки.
